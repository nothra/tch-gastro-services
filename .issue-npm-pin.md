## Kontext

**Kategorie:** Supply Chain / unverifizierte Fremd-Abhängigkeit in CI (OWASP A08 – Software and Data Integrity Failures).

Der Job `factory-poll` in `.github/workflows/factory-poll.yml` installiert die Runtime mit:

```yaml
- name: Runtime bereitstellen (claude-CLI + yq)
  run: |
    npm install -g @anthropic-ai/claude-code
    claude --version
    sudo bash scripts/install-yq.sh
```

Die `yq`-Hälfte dieses Schritts ist seit Task 258 gepinnt und SHA-256-verifiziert. Die
`npm install -g`-Hälfte daneben ist **weder versions-gepinnt noch integritätsgeprüft**:
jeder Lauf zieht die zum Zeitpunkt des Laufs neueste Version aus der npm-Registry.

**Angriffsfläche:** Genau dieser Job hält `ANTHROPIC_API_KEY` als Env-Var und läuft mit
`contents: write` + `issues: write` auf dem `GITHUB_TOKEN`. Ein kompromittiertes oder
versehentlich fehlerhaftes Release des Pakets (bzw. einer transitiven Abhängigkeit) führt
Code im selben Prozessraum wie das Secret aus und kann anschließend auf `main` pushen.
Dieselbe Risikoklasse, wegen der Task 258 den yq-Download gehärtet hat – nur mit höherem
Schadenspotenzial, weil hier ein Secret im Kontext liegt.

**Warum eigener Task:** `spec-258` schließt Änderungen an anderen `wget`/`curl`/npm-Downloads
ausdrücklich aus (§Nicht inbegriffen: „Keine Änderung an anderen `wget`/`curl`-Downloads im
Repo (z. B. `claude-code`-Installation in `factory-poll.yml`)"). Gefunden im
`/security-review` zu Task 258 als angrenzendes, nicht durch den PR eingeführtes Risiko.

## Lösungsvorschlag

1. Version pinnen: `npm install -g @anthropic-ai/claude-code@<version>` statt implizit `latest`.
2. Integrität erzwingen: `npm install --ignore-scripts` (verhindert Postinstall-Skripte)
   und/oder Installation über ein Lockfile-gestütztes `npm ci` in einem eigenen Verzeichnis.
3. Analog zu `scripts/install-yq.sh` einen kanonischen Seam (`scripts/install-claude-cli.sh`)
   einführen – die Regel in `CLAUDE.md` §Guardrails sieht dieses Muster für weitere
   Fremd-Binaries bereits vor.
4. Zusätzlich erwägen: Bump-Automatisierung (Dependabot/Renovate) für den Pin, damit der Pin
   nicht altert.

Referenz: Issue 258, PR 277.
